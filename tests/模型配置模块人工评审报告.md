## 修复记录

### Page Object: model_config_page.py
- **问题1**：`is_loaded()` 使用 `div.agent-panel-content` + "服务商与模型"，实际 DOM 为 `div.agent-panel-body` + "模型库"
- **修复**：修正选择器和标题文本
- **问题2**：`get_page_title()`、`has_skeleton_or_spinner()` 使用 `agent-panel-content`
- **修复**：统一改为 `agent-panel-body`
- **问题3**：搜索框 placeholder 为"搜索服务商名称..."而非"搜索服务商"
- **修复**：更新 `search()`、`clear_search()`、`has_search_input()` 的选择器
- **问题4**：`get_provider_names()` 取卡片文本第一行（头像字母），实际名称在第二行
- **修复**：改为 `lines[1].strip()`
- **问题5**：`fill_model_form()` 使用 `input[type=text]`，实际输入框无 type 属性
- **修复**：改为 `input[data-slot='input']`
- **问题6**：`click_model_test()` 等待 3 秒太长，"测试通过"文本 5 秒后消失
- **修复**：等待改为 500ms，由测试用例自行控制等待时间

### test_model_001
- **问题**：缺少"新建服务商"按钮检查
- **修复**：添加 `has_add_provider_button()` 断言

### test_model_002
- **问题1**：断言检查的是响应体而非请求体（interceptor 只捕获响应），`apiKey` 在响应中被脱敏为 `keyHint`
- **修复**：改为验证响应中 `keyHint` 为掩码格式（`***` 开头）
- **问题2**：teardown 错误监控捕获 `fetch-models` 500（假 URL 导致）
- **修复**：在 conftest.py 白名单中添加 `fetch-models` 和 "Failed to load resource" 500

### test_model_004
- **问题**：原预期 API Key 为空时拦截，实际系统允许不填 Key 创建 Provider
- **修复**：改写为验证"不填 API Key 也能创建 Provider"

### test_model_008
- **问题**：`fill_model_form` 输入框选择器不匹配导致表单未填写
- **修复**：Page Object 中改为 `input[data-slot='input']`

### test_model_010
- **问题1**：用例名"测试连接"不准确，实际操作是"获取模型列表"
- **修复**：改名为 `test_model_010_fetch_provider_models`
- **问题2**：反馈检查只看页面文本，未检查弹窗
- **修复**：添加弹窗检查（标题"可用模型列表"、"发现 N 个可用模型"）

### test_model_011
- **问题**：判断标准太宽松（页面文本包含"成功"或 API 有调用即通过）
- **修复**：严格校验卡片文本中出现"测试通过"

### test_model_015
- **问题**：操作第一个 Provider 的公开开关，影响已有数据
- **修复**：改为先创建自己的 Provider，操作后清理

### conftest.py
- **问题**：`_page_error_monitor` 将 `fetch-models` 500 和浏览器原生 500 报错视为测试失败
- **修复**：添加白名单，跳过 `fetch-models`、`CONFIG_TEST_REQUEST_FAILED`、`Failed to load resource` 500

## 全局问题

- **DOM 面板定位**：模型配置页面内容在 `div.agent-panel-body` 中，与 API 密钥页面一致
- **输入框选择器**：弹窗中的输入框使用 `input[data-slot='input']`，不带 `type=text` 属性
- **Provider 卡片文本结构**：第一行为头像字母，第二行为 Provider 名称，需注意提取逻辑
- **测试结果时序**："测试通过"文本约 2 秒后出现、5 秒后消失，需要精确控制等待时间
