## 评审过程中的主要修复

### 1. DOM 选择器修正
- `agent-panel-content` → `agent-panel-body`（主内容区选择器错误，TC-ORG-001）

### 2. 移除成员选择器重写
- 原选择器 `body.locator("div").filter(has_text=target_user).filter(has_text="@")` 太宽泛，误匹配到包含「删除组织」按钮的大容器，导致 ORG_001 被意外删除
- 改为精确的成员行选择器：`div.group` + hover + `svg.lucide-trash-2` 垃圾桶按钮
- 确认弹窗从 `[role=dialog]` 改为页面级 `get_by_role("button", name="确认移除")`（弹窗实际是 `alertdialog`）

### 3. 测试组织改用 ORG_AUTO_TEST
- TC-ORG-006、TC-ORG-008 从 ORG_001 改为 ORG_AUTO_TEST（用户指定）

### 4. 移除成员测试重写（TC-ORG-008）
- 原代码只检查文本中有角色信息，不执行移除操作
- 重写为完整流程：确保成员在列表 → hover → 垃圾桶 → alertdialog 确认 → 验证成员消失 + 数量减少

### 5. 删除组织测试重写（TC-ORG-011）
- 原代码点击删除后关闭弹窗，靠 API 清理，不真正测试 UI 删除
- 重写为完整流程：API 创建 → UI 点击删除 → alertdialog 点「确认删除」→ 刷新验证组织消失 + API 二次确认

### 6. 编辑组织测试重写（TC-ORG-012）
- 原代码假设弹窗编辑，实际是内联编辑（名称 input + 保存/取消按钮）
- 重写为：编辑 → 修改名称 → 保存 → 刷新验证持久化

### 7. conftest 白名单新增
- `Failed to fetch` + `/web/environments/` — AgentPanelLayout 环境轮询 SPA 瞬态错误

## 系统行为发现

### 成员管理 DOM 结构
- 成员行使用 `div.group`，操作按钮 hover 时才显示（`opacity-0 group-hover:opacity-100`）
- 删除按钮是带 `svg.lucide-trash-2` 的 button，无 aria-label
- 移除确认弹窗使用 `role="alertdialog"`，按钮为「取消」/「确认移除」
- Owner 行无操作按钮

### 编辑组织为内联模式
- 点击「编辑」不弹窗，组织名称变为 input
- 「编辑」按钮变为「保存」+「取消」
- 仅名称可编辑，无描述字段

### 移除成员无 toast
- 添加成员有 toast 提示
- 移除成员无 toast 提示（通过成员列表变化验证）
