## 第 5 条 `test_skill_upload`

**用例编号**：TC-SKILL-015
**用例说明**：验证内部 API 上传技能文件

**评审结论**：⚠️ 问题已修复 → ✅ 通过

**评审问题**：
- [x] 原实现通过 UI 上传，但技能上传使用 `webkitdirectory`（文件夹上传），Playwright 不支持，导致用例永远 skip
- [x] 原实现有 4 个 `pytest.skip` 分支，多处条件不满足时直接跳过

**修复措施**：
1. 完全重写为内部 API 测试：`POST /web/config/skills/upload`
2. 消除所有 `pytest.skip` 分支
3. 增加验证：上传后列表中能查到新技能
4. 增加清理：上传完成后通过 `DELETE /web/config/skills/:name` 删除测试技能

## 第 6 条 `test_skill_delete_via_ui`

**用例编号**：TC-SKILL-017
**用例说明**：内部 API 上传临时技能 + 页面 UI 删除验证

**评审结论**：⚠️ 问题已修复 → ✅ 通过

**评审问题**：
- [x] 原实现直接删除系统中第一个技能，属于破坏性测试，会删除生产数据
- [x] 确认对话框用了 5 种选择器猜测，如果都不匹配则不确认

**修复措施**：

3. 使用精确选择器 `[role='alertdialog'] [data-slot='alert-dialog-action']` 点击确认
4. 增加同名残留清理逻辑，防止重复运行冲突
5. 验证：DELETE API（`DELETE /web/config/skills/:name`）返回 200 + 页面上该技能消失

## 全局问题

1. **webkitdirectory 限制**：Playwright 不支持 `webkitdirectory` 文件夹上传，涉及上传的 UI 测试需改为 API 调用
2. **应用缓存导致间歇失败**：前端使用应用级缓存（sessionStorage/localStorage），后续测试可能因缓存数据而跳过 API 调用，需要主动清除
3. **`pytest.skip` 滥用**：原实现中多处使用 `pytest.skip` 掩盖真问题，已全部修正为 `assert` 失败
4. **统一使用内部 API**：所有 API 测试用例统一使用 `/web/config/skills` 内部接口，避免混用外部 `/api/skills` 接口
